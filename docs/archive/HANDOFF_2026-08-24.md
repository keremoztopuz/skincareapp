## 2. PROXY — `~/Desktop/skincare-proxy/` (git'te DEĞİL)

FastAPI, tek endpoint. 22/22 test (`pytest`, Vertex çağrısı sahte — test asla para harcamaz).

| şey | değer |
|---|---|
| Canlı URL | `https://skincare-proxy-13342137011.europe-west1.run.app` |
| GCP projesi | `skincare-506514` (Vertex faturası da burada) |
| Bölge | `europe-west1` |
| Servis hesabı | `skincare-proxy@skincare-506514.iam.gserviceaccount.com` |
| Günlük tavan | `GEMINI_DAILY_CALL_LIMIT=500` (Firestore'da UTC-günü sayaç, atomik) |
| Maliyet | analiz başına ~$0.0007 → ~1400 analiz ≈ $1 |

### Endpoint

- `POST /v1/analyze` — multipart: `image` (JPEG ≤4MiB), opsiyonel `skin_type`, `age`. Başlık: `Authorization: Bearer <CLIENT_SHARED_SECRET>`. Yanıt: `{version, request_id, model, latency_ms, scores:{altı sayı}}`.
- `GET /health` — **`/healthz` DEĞİL**: Google'ın ön ucu run.app'te `/healthz`'i kendine ayırıyor ve konteynere ulaşmadan 404 basıyor. Bu bir kez ısırdı, yol değiştirildi.

### Görsele yapılanlar (sunucuda)

Sihirli sayıyla JPEG doğrulama → EXIF yönü uygula, **tüm EXIF sil (GPS!)** → uzun kenar 768px (Gemini 768² karo başına faturalar; tek karo = en büyük maliyet kaldıracı) → q85. Görsel diske yazılmaz, loglanmaz.

### Kimlik ve koruma

- **Vertex için API key YOK** — Cloud Run'da servis hesabının ADC'si. Sızacak kimlik bilgisi yok; kullanıcının aldığı Gemini Developer key'i **kullanılmıyor**.
- Tek sır: `CLIENT_SHARED_SECRET` (`.env`'de + Secret Manager'da + uygulamada `AnalysisConfig.swift`). Bu bir hız kesici, kilit değil (`strings` ile ipa'dan çıkar). Asıl koruma tavan. App Attest = Faz 2, yapılmadı.
- İstemcide **retry yok** — proxy kendi içinde deniyor; istemci retry'ı çift harcama olur.
- Firestore erişilemezse **kapalı** başarısız olur: sayaç yoksa çağrı yok.

### Deploy sırasında ısırılan üç tuzak (tekrarı önlemek için)

1. Yeni projede Cloud Build'in compute hesabına `roles/cloudbuild.builds.builder` + `roles/logging.logWriter` + `roles/artifactregistry.writer` vermek gerekti (hata mesajları bu yüzden boştu).
2. Debian imajında `proxy` adında sistem kullanıcısı **zaten var** (UID 13) — `useradd proxy` çakıştı, `appuser` yapıldı.
3. `/healthz` GFE tarafından yutuluyor (yukarıda).

### Yönetim (kullanıcı için)

- Tavan değiştir: `.env`'de sayıyı değiştir → **yeniden deploy gerekir** (canlı değer Cloud Run env'inde): aşağıdaki deploy komutunda `GEMINI_DAILY_CALL_LIMIT` değerini güncelle.
- Fatura: console.cloud.google.com → Billing. **Bütçe uyarısı henüz kurulmadı** (yapılacaklar'da).
- Kod değişince yeniden deploy:
```bash
cd ~/Desktop/skincare-proxy && gcloud run deploy skincare-proxy --source . --region europe-west1 --project skincare-506514 --service-account skincare-proxy@skincare-506514.iam.gserviceaccount.com --allow-unauthenticated --set-secrets CLIENT_SHARED_SECRET=CLIENT_SHARED_SECRET:latest --set-env-vars GOOGLE_CLOUD_PROJECT=skincare-506514,GOOGLE_CLOUD_LOCATION=europe-west1,GEMINI_DAILY_CALL_LIMIT=500,DAILY_LIMIT_BACKEND=firestore --min-instances 0 --max-instances 3 --concurrency 20 --cpu 1 --memory 512Mi --timeout 60 --quiet
```
- Yerel çalıştırma (.venv yok, `uv` kullanılıyor):
```bash
cd ~/Desktop/skincare-proxy && uv run --no-project --python 3.12 --with-requirements requirements.txt uvicorn app.main:app --reload --port 8080
```
